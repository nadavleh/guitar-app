# Cavaquinho Progressions — Design

**Date:** 2026-07-12
**Status:** Approved (Nadav granted build-without-prompt autonomy; iterate after).
**Platforms:** Android + chorect-web parity.

## Goal
Turn the app into a cavaquinho-learning tool centered on **functional chord sequences** (samba/choro turnarounds like the *quadradinho*), playable and visualizable across the neck in any key.

## Source material
- PDF `SequÍncias de acordes para cavaquinho.pdf` (Betto Correa) — functional sequences shown as cavaquinho chord diagrams. Extracted functional content (all modules are the same sequence transposed across 7 keys, so we store ONE functional definition per sequence and transpose):
  - **Quadradinho (basic major)** — `I VI7 ii V7` (C A7 Dm G7).
  - **Basic minor** — `i I7 iv V7` (Cm C7 Fm G7).
  - **Médio major (extended turnaround)** — `I VI7 ii V7 v I7 IV iv iii VI7 ii V7 I`.
  - **Médio minor** — analogous extended minor (approximate for v1; refine later).
  - **II–V–I major** — `ii7 V7 Imaj7`.
  - **Campo harmônico maior (diatonic field)** — `I ii iii IV V vi vii°`.
- PDF `Song artist chords v03.pdf` — ~29 pages of `Song / Artist / functional-progression` rows (e.g. `vi–IV–I–V`, `I–V–vi–IV`, `I–vi–IV–V`). Imported into the song library, keyed by degrees.

## Decomposition (independent sub-projects)
1. **Tuning default → traditional DGBD** (foundational, small).
2. **Cavaquinho "Progressions" screen** (the core): a cavaquinho-only menu entry → looper + fretboard integrated; pick a functional sequence; transpose; scroll voice-led shapes along the neck.
3. **Tuning-editor scroll-jump fix** (small, independent).
4. **Song-library import from PDF #2** (additive data).
5. **English translation of PDF #1** (a `docs/` markdown deliverable).

---

## 1. Traditional tuning (DGBD)
`Tunings.kt`: add `cavaqDgbd = Tuning.of("D4","G4","B4","D5")` (highest string D, not E5). Make it the cavaquinho **default** (`cavaquinhoDefault` / default-name → "DGBD") and first in `cavaquinhoPresets` (keep DGBe as a secondary preset). Mirror in web `tunings.ts`. This matches the PDF's diagrams (which assume DGBD). Existing installs keep their saved tuning; only never-configured cavaquinho defaults change.

## 2. Cavaquinho Progressions screen
### Data model (theory, pure, reused machinery)
Sequences are `EarTraining.NamedProgression`s (an `AdvChord` list = `(semitone, quality, roman)` relative to the tonic) — the SAME type the advanced/circle ear-training already resolves and voice-leads. New file `theory/.../CavaqSequences.kt`:
```kotlin
data class CavaqSequence(val id: String, val namePt: String, val nameEn: String,
                         val prog: EarTraining.NamedProgression)
val CAVAQ_SEQUENCES: List<CavaqSequence>   // the sequences above, defined in C
```
Mirrored in web `theory/cavaqSequences.ts`. Unit-tested (each resolves to the expected chords in C; count/roman sanity).

### Screen (new `Sheet.CavaqProgressions`)
A single screen combining:
- **Sequence picker** — dropdown/chips of `CAVAQ_SEQUENCES` by name (Quadradinho, Basic minor, Médio, II‑V‑I, Campo harmônico…).
- **Key transpose** — starts in C; ± semitone clicker (reuses the existing transpose pattern) + a key dropdown.
- **Looper** — plays the sequence in a bar loop at a BPM (reuse the ear-training progression looper / `AudioEngine.playChord`, cavaquinho timbre). Play/Stop.
- **Fretboard** — the existing `FretboardView`/`FretboardCanvas` showing the **currently-sounding chord's shape**, following playback (like the ear-training follow-along board). Uses the cavaquinho tuning.
- **Shape scroller** — the sequence's shapes are voice-led (`VoiceLeading.pickMinMovement`: each chord's shape is the least-motion voicing from the previous). A **"position" control** (◀ ▶ or a slider) chooses the STARTING shape/neck-region; the rest of the sequence is voice-led from it, so the user can scroll the whole sequence up/down the neck. Shapes generated by `ChordShapeGenerator(cavaquinho tuning)`.

### Menu wiring
Add `TabDest.CavaqProgressions` (Sheet.CavaqProgressions, label "Progressions", an icon). It appears in the tab bar / More **only when `instrument == Cavaquinho`** (guarded in the shell's tab list + reachable from More). Selecting cavaquinho surfaces it; switching to guitar hides it.

### State
New `CavaqProgState` (Android) / `cavaqProgState.ts` (web): current sequence id, key (default C / PitchClass.C offset), BPM, isPlaying, positionIndex (shape scroller), current bar, current shape (for the follow board). Looper coroutine/token like the ear looper. Persists last-picked sequence + key (DataStore/localStorage).

## 3. Tuning-editor scroll-jump fix
Changing a string's tuning triggers a full rebuild that resets the settings sheet's scroll to the top. Fix: preserve the scroll position across the tuning-change rerender (Android: the tuning editor is in a `verticalScroll(rememberScrollState())` — ensure the state is hoisted/remembered across the recomposition, not re-created; web: capture/restore the scroll container's `scrollTop` across the rerender, mirroring the library-overlay scroll fix). Applies to the tuning editor in Options/Settings.

## 4. Song-library import (PDF #2)
Parse the song list (a build-time script `tools/import_song_library.py` reading the PDF text) → group songs by functional progression → emit `SongExample` entries merged into `ProgressionSongs.major`/`minor` under the matching `degrees` key (`vi–IV–I–V` → `[6,4,1,5]`, `I–V–vi–IV` → `[1,5,6,4]`, `I–vi–IV–V` → `[1,6,4,5]`, etc.). Cap per progression to a sane number (e.g. ≤ ~40 recognizable entries) to keep the list usable and the file reasonable; dedup by (title, artist). Both platforms (Kotlin map + TS map kept in sync by the script). Only degree-progressions the library already exposes get songs; unmapped functional labels are skipped and logged.

## 5. English translation of PDF #1
Produce `docs/cavaquinho-sequences-EN.md` — the PDF's structure + sequence names translated to English (module headings, sequence titles, and the functional content per sequence), so the material is usable in English. (Text deliverable; not shipped in-app.)

## Testing
- Theory: `CavaqSequences` resolve correctly in C (chords + romans); transposition sanity. `ProgressionSongs` import keys resolve to real degree progressions (no orphan keys). Existing theory/audio tests stay green.
- Build: assembleDebug + web tsc/vite/deploy.
- Manual (Nadav): pick cavaquinho → Progressions tab appears; pick Quadradinho → C A7 Dm G7 loops; transpose; scroll shapes along neck; DGBD default; tuning editor keeps scroll.

## Milestones (ship incrementally; version bumps as we go)
M1 DGBD default + tuning-editor scroll fix (quick foundational). 
M2 CavaqSequences data + theory tests. 
M3 Progressions screen (state + looper + fretboard + picker + transpose + shape scroller) Android. 
M4 Web mirror of the screen. 
M5 Song-library import (PDF #2). 
M6 English translation doc. 
Ship as **v2.5.0** (major feature) after M4 at latest; M5/M6 can fold in.

## Out of scope (later)
- Exact PDF voicing fidelity (app generates cavaquinho shapes; PDF's specific fingering is one option among them).
- The "dissonant substitutions" apostila (a follow-on).
- Non-cavaquinho use of the Progressions screen.
